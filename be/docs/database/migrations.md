# Database Migrations Guide

FocusBuddy uses [Alembic](https://alembic.sqlalchemy.org/) alongside SQLAlchemy for database schema version control. 

**Important Principle:**
Alembic migration is **not** the place to design Models. The SQLAlchemy Model classes in `app/models/` are the Single Source of Truth for ORM design. Alembic simply detects changes between those models and the current database schema, and generates SQL scripts to synchronize them.

## Common Workflows

### 1. Check current migration state
To see which revision your database is currently on:
```bash
alembic current
```

### 2. View migration history
To see the timeline of all migrations:
```bash
alembic history
```

### 3. Generate a new migration
Whenever you modify, add, or delete an SQLAlchemy Model, you must generate a migration script:
```bash
alembic revision --autogenerate -m "description of changes"
```
*Note: Always review the generated script in `alembic/versions/` before applying it. Do not blindly run `upgrade head` if the autogenerated script includes unintended drops or alters.*

### 4. Apply migrations
To upgrade the database to the latest revision:
```bash
alembic upgrade head
```

### 5. Rollback a migration
If you need to undo the last applied migration:
```bash
alembic downgrade -1
```

## Migration Notes for Learning Activity Module
During the implementation of the Learning Activity Module, it was verified that the Learning Models (`LearningGoal`, `StudySession`, `StudyTask`, etc.) were already included in the initial database schema (`e324c12bc635_initial_database_schema.py`). Thus, running `--autogenerate` for the Learning Activity Module yielded an empty migration script, which was safely discarded. No new database revision was necessary.
